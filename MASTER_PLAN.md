## План багатокористувацької архітектури

1. Винести лоти, версії чернеток, перевірки, HOLD і історію операцій у PostgreSQL. Кожен запис належить акаунту або робочому простору. Доступ перевіряти через членство та роль на сервері, з окремими тестами на перехресний доступ. Ключі фото в об’єктному сховищі мають включати простір, лот і версію, а керовані сервером короткоживучі URL обмежують завантаження і читання.
2. Розділити HTTP-маршрути, предметну логіку та клієнтів Google, OpenAI, eBay і перевізників. Для кожного магазину зберігати окреме OAuth-підключення зі шифруванням токена, мінімальними дозволами, від’єднанням і обробкою відкликання. Відслідковувати SKU та Offer у межах підключення магазину. Прив’язати право публікації до ролі й дозволу власника.
3. Винести довгі операції в чергу. Ідемпотентний ключ включає акаунт, магазин, лот, версію і тип операції. Зберігати стан зовнішнього запису перед відправленням, звіряти його після тайм-ауту й лише потім дозволяти повтор. Обмежувати паралельність за магазином і провайдером. Збирати затримку, кількість запитів, гроші, частку ручних перевірок і причини зупинки. Продуктивність міряти на стійких 100 лотах за робочий день з урахуванням відновлення.
4. Вести окремо твердження, джерело, метод перевірки, суперечності, підтвердження продавцем і стан експорту. Для кожного маршруту окремо перевіряти правила майданчика, правила перевізника і вимоги митниці для конкретного товару й напрямку. У фінальній перевірці фіксувати ревізії правил і даних лота.
5. Додати серверні права за тарифом, ліміти обробки та ідемпотентний журнал змін підписки. Для адміністраторів виділити ролі підтримки та фінансів, журнал доступу, мінімальний перегляд даних і статистику відмов. Публічний багатокористувацький доступ потребує заміни нинішніх процесних кешів, глобальної OAuth-конфігурації та спільного HOLD.
6. Зберегти PWA для пілота. Для Play підготувати Android-клієнт з Photo Picker, фоновим відновлюваним завантаженням і OAuth через системний браузер. Збірки debug APK для приймання та release AAB для Google Play формувати окремими процесами CI. Відкрити внутрішній трек, перевірити встановлення на фізичних Android в Україні, заповнити Data safety, видалення акаунту, політику конфіденційності та актуальні вимоги Play до підписок і цільового SDK.

## Перевірка власником

У корені чистої копії гілки з Python 3.12 запустіть:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest -v
```

Для ручної перевірки використайте окремий каталог даних, чисте оточення без робочих ключів інтеграцій і локальний сервер:

```bash
test_data=$(mktemp -d)
env -i PATH="$PATH" APP_SECRET=local-p094-test \
  ALLOW_PAID_AI=0 ENABLE_LIVE_PUBLISH=0 \
  ACTIVE_LOT_CHECKPOINT_DIR="$test_data/checkpoints" HOLD_QUEUE_DIR="$test_data/hold" \
  .venv/bin/python -m flask --app app run --host 127.0.0.1 --port 5000
```

Відкрийте `http://127.0.0.1:5000/mobile`. Завантажте 24 JPEG, відкрийте редактор, виберіть головне фото з кінця списку, затвердьте фото, додайте лот у HOLD та відкрийте його після перезапуску з тим самим каталогом і ключем. Перевірте окремо `test_quality.CategoryTests.test_reported_lot_failure_patterns` командою `.venv/bin/python -m unittest -v test_quality.CategoryTests.test_reported_lot_failure_patterns`. Оригінальні LOT058–060 потрібні для наступного прогону реального розпізнавання.
