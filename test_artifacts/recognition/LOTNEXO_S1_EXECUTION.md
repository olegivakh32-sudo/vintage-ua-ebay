Запис про запит і його резерв синхронізується на диску до відправлення. Зайві виклики, редиректи, перевищені ліміти й неможливість запису зупиняють виконання. Хеші входів перевіряються перед прогоном.
- HTTP-помилка, тайм-аут, невідома тарифікація, неповна відповідь, відхилення від схеми або відсутній пошук зупиняють S1. Відомі витрати записуються навіть за `max_output_tokens`. Невизначена сума лишається зарезервованою. Автоматичних повторів немає.
- Артефакт `lotnexo-s1-evidence` зберігає журнал, доступні сирі відповіді, картки, час, витрати, експорти та код зупинки. Картки створюються через маршрути чернетки в ізольованому HOLD. Невирішена категорія, ціна та доставка залишаються відкритими. Публікація заблокована. Спроба критичного допуску зупиняє етап.
- Бронювання обмежує відправлення за зафіксованим тарифним профілем. У разі несподіваної тарифікації застосунок зупиняє решту запитів. Суму вже облікованого провайдером виклику клієнт не може змінити.

## Оцінювання після фіксації відповідей

Збережіть відповіді обох систем і хеші файлів до відкриття еталонів. Незалежний оцінювач запускає локальний звіт, який рахує строгі збіги, невідомі відповіді, розбіжності й знаменник кожної метрики. Мінімум S1 — 9 правильних типів із 10. Порожня або нерозбірлива ідентифікація входить до знаменника. Допуск до S2 потребує окремої оцінки критичних помилок. Ціль ≥90% і паритет ChatGPT оцінюються на повній контрольній вибірці.

У зафіксованому S1 еталони типу є для 10/10, матеріалу та періоду для 7/10, точного бренду й моделі для 1/10. Дев’ять товарів мають документальні габарити, два — документальну номінальну масу. Фактичних вимірів пакунків, незалежно перевірених цін угод і живих листових категорій у цьому наборі поки немає. Ці показники лишаються без числової оцінки до отримання доказів.

```sh
python s1_review.py \
  test_artifacts/recognition/lotnexo-acceptance-stages-candidate.json \
  test_artifacts/recognition/lotnexo-acceptance-56-enriched.json \
  results/predictions.json --chatgpt chatgpt.json > s1-review.json
```

| Оцінка | Що перевіряє незалежний оцінювач |
| --- | --- |
| Ідентифікація, бренд, модель, матеріал | Строгий збіг з еталоном та окремо змістовий збіг. Назву компонента або сімейства оцінюють за підтвердженістю конкретного варіанта. |
| Габарити й маса | Узгодження з документом для тієї самої конфігурації, компонента й одиниці. Фактичні виміри, довідка та розрахунок оцінюються окремо. |
| Джерела | Доступність URL, точний уривок, незалежність джерел, зв’язок із конкретним товаром. |
| Категорія й SEO | Листовий ID, повна гілка, версія Taxonomy, обов’язкові аспекти. Окремо заголовок до 80 символів, точність опису та непідтверджені заяви. |
| Ціна й доставка | Фактичні суми зіставних завершених угод, покриття й похибка. Для доставки окремо арифметика, виміри пакунка й дозволеність маршруту. |

## Доступ до офіційної таксономії eBay

1. У [eBay Developer Program → Application Keys](https://developer.ebay.com/my/keys) відкрийте **Production → User Tokens → Get OAuth Application Token**. Для цього читання достатньо токена застосунку. Seller refresh token і дозвіл від магазину тут не потрібні. Sandbox має окремі ключі. [Офіційна інструкція eBay](https://developer.ebay.com/develop/guides/sell/authorization)
2. У локальному терміналі репозиторію введіть короткоживучий токен без показу в терміналі. Звіт містить статус, ID та версію дерева. Для вже знайденого листового ID можна додати `--category-id ВАШ_ID` та отримати обов’язкові характеристики.

```bash
read -r -s -p 'eBay Application token: ' VINTAGE_EBAY_TAXONOMY_TOKEN
export VINTAGE_EBAY_TAXONOMY_TOKEN
python ebay_sandbox_probe.py --production-taxonomy --connect --marketplace EBAY_US
unset VINTAGE_EBAY_TAXONOMY_TOKEN
```

3. Для автоматичного отримання токена налаштуйте `VINTAGE_EBAY_TAXONOMY_CLIENT_ID` (App ID) та `VINTAGE_EBAY_TAXONOMY_CLIENT_SECRET` (Cert ID) у захищеному середовищі діагностики. Пробник отримує токен застосунку за Client Credentials і виконує GET-запити до Taxonomy. [eBay Taxonomy API](https://developer.ebay.com/develop/api/sell/taxonomy_api)

Токен і секрет зберігаються поза Git. S1 може виконати розпізнавання до авторизації eBay. Для оцінки категорій незалежний перевіряльник фіксує листові категорії та версію дерева до відкриття відповідей. Їх додають окремим еталоном із власним хешем.

## Фактична спроба S1 — 27.11.2026

Погоджену ревізію й точне правило тега підтверджено. Перед запуском пройшли 16 локальних тестів бюджетного захисту. Ізольована підготовка та звірка фото завершилися успішно. Безкоштовна перевірка метаданих моделі зупинила першу спробу з **HTTP 401 / expired_secret_key**. Для Responses API не виконувалися наступні запити, зокрема генерація й підрахунок вхідних токенів. Бронювання та платний крок пропущено. [GitHub Actions](https://github.com/olegivakh32-sudo/vintage-ua-ebay/actions/runs/45987944917)

Реальна обробка товарів не почалася. Для кожного з 10 товарів зафіксовано `NOT_RUN`, **$0,00** і відсутність вимірів точності та швидкості. 34 секунди — час завдання GitHub Actions, включно з підготовкою. Цей час не входить до метрики обробки товару. Точність S1 поки не оцінено. Діагностичний ZIP збережено побайтово і звірено за SHA‑256. [Аудит](lotnexo-s1-45987944917-audit.json) · [Оригінальний ZIP](lotnexo-s1-45987944917-evidence.zip)

Workflow підтверджено у стані `disabled_manually`. Для подальшої роботи замініть прострочений `P094_PILOT_OPENAI_API_KEY` у **GitHub → Settings → Environments → p094-vision-pilot → Environment secrets**. Наступним кроком буде безкоштовна авторизація. Для запуску з новим ключем потрібне окреме погодження.
