# Сліпе порівняння LOTNEXO і ChatGPT

## Зафіксований набір для першого живого прогону

Використовуйте `MV-101`, `MV-102`, `MV-103` з нового ZIP. Пакет має 7 JPEG і `photos.json`, без еталонів. SHA-256 `c362598737440888911cde10a9a508367236d16495338aff4b814a747b14764f`. Окремий архів містить п’ять вихідних файлів, зокрема авторський монтаж. У сліпому ZIP три його ракурси розкладено на окремі кадри. Використовуйте саме сліпий ZIP для обох систем. Атрибуції, умови ліцензій та еталони збережено в окремому маніфесті для звірки. [Маніфест](lotnexo-live-pilot-sources.json)

Workflow використовує заморожений ZIP із репозиторію. [Пакет](lotnexo-live-pilot-blind.zip)

```sh
python prepare_multiview_cohort.py test_artifacts/recognition/lotnexo-live-pilot-sources.json lotnexo-live-pilot-blind.zip
python blind_live_pilot.py lotnexo-live-pilot-blind.zip
python blind_live_pilot.py --models
```

Сухий запуск працює локально. `--models` читає лише метадані за наявності ключа в ізольованому середовищі. Майбутній платний запуск потребує окремого погодження, успішного читання моделі й доступу до лічильника токенів. Після погодження прив’язати `APPROVE_LOTNEXO_050` до SHA-256 сліпого ZIP, запустити `blind_live_pilot.py lotnexo-live-pilot-blind.zip --execute NEW_REPORT_DIR` один раз і використати новий каталог звіту. Збережені файли `run.json` і `predictions.json` містять відповідь, час, токени й прогнози. Сума $0,43335 резервує всю серію із шести можливих запитів GPT‑6 Luna Standard. Запити за межами послідовності відхиляються. Перевірка токенів безкоштовна.

```sh
python recognition_benchmark.py test_artifacts/recognition/lotnexo-live-pilot-sources.json \
  NEW_REPORT_DIR/predictions.json --chatgpt-predictions chatgpt.json
```

На кожне поле, яке не збіглося з еталоном, записати конкретну причину й кадр або URL для перевірки. Ознаки, яких немає у візуальному звіті, перевірити за оригіналом і OCR. Ознаки, які є у звіті та зникли до картки, перевірити за рішеннями про джерело й конфлікт. Окремо рахувати помилки OCR, невдалий пошук, помилкову атрибуцію й невідомі покази. Документальні габарити не оцінюються як покази ваг або лінійки. Картка з непідтвердженою категорією чи невідомою доставкою залишається на перевірці. Покриття й фактичні помилки ще потребують запуску.

## Однакові вхідні дані

Підготовчі лоти `MV-003`, `MV-006` і `MV-009` містять дев’ять фото. Їх можна використовувати для перевірки процедури. Для оцінки обох маршрутів замінити або доповнити набір лотом із читабельною заводською етикеткою і зафіксувати новий SHA-256 до першого прогону.

```sh
python prepare_multiview_cohort.py test_artifacts/recognition/lotnexo-multiview-sources.json \
  lotnexo-comparison-3-blind.zip --lot MV-003 --lot MV-006 --lot MV-009
```

SHA-256 підготовленого пакета в поточному середовищі — `9ff183ff1cf5fb9f2f06e699e0114b66071e482141bf35e65562eca39e7447ab`. Звірити кожен JPEG з `photos.json` і передати обом системам лише фотографії одного лота в порядку номерів та нейтральний ID. Для ChatGPT створити окремий сеанс на кожен лот без історії або пам’яті, вибрати й зафіксувати режим із фото та вебпошуком. Для LOTNEXO зафіксувати ревізію коду, моделі, параметри та контрольну суму каталогу загального призначення. Живий прогін LOTNEXO потребує окремого погодження бюджету.

Маніфест з джерелами й еталони передаються тільки оцінювачу. Каталог LOTNEXO фіксується до відбору закритих лотів. Імпортувати рядки контрольної вибірки або підказки з попередніх відповідей у каталог, запит чи кеш заборонено. Обидві системи можуть самостійно знаходити ті самі публічні документи. Для LOTNEXO використовувати ізольовані нові лоти, щоб старі відповіді не потрапили в прогін.

## Завдання для обох систем

Застосувати наведене завдання в ChatGPT. LOTNEXO виконує його штатними модулями з тими самими вимогами до результату. Його поля експортуються до того самого формату.

> Досліди один товар для чернетки eBay US за прикріпленими фото в порядку номерів. Назви предмет і його призначення. Точно перепиши видиме маркування, знайди виробника і модель або задокументуй кілька можливих варіантів. Звір їх з документацією виробника, архівом або музейним записом і незалежним джерелом. Для кожного значення вкажи стан доказу (видиме чи підтверджене, довідка для моделі, гіпотеза або невідомо), номери фото, URL та короткий уривок, що його підтримує. Розділи стан поверхні, справність, видимі дефекти й комплектність. Для габаритів і маси конкретного екземпляра потрібні читабельні покази. Номінальні дані з документації записуй окремо. Запропонуй шлях і ID листової категорії eBay з обґрунтуванням за типом і призначенням. Вкажи головний кадр та окремо технічні фото. Для оцінки ціни відокрем підтверджені продажі, активні пропозиції та оцінки. Склади заголовок англійською до 80 символів і короткий опис із підтверджених фактів. Поверни JSON за формою нижче. Невідомі значення позначай `null` і поясни, якого кадру або документа бракує.

```json
{
  "lot": "<нейтральний ID>",
  "identity": null, "brand": null, "model": null, "material": null,
  "country": null, "period": null, "condition": null, "completeness": null,
  "defects": null, "ocr": null, "category_id": null, "category_path": null,
  "measurement": {"weight_kg": null, "length_cm": null, "width_cm": null, "height_cm": null},
  "nominal_specs": {}, "evidence": {}, "unknown_reasons": {}, "market": {},
  "title": null, "description": null, "admitted": false
}
```

Додавати `product_photos`, `evidence_photos` і `main_photo`, якщо ролі визначені. `admitted` для LOTNEXO брати з результату штатного контролю, а для ChatGPT фіксувати рішення моделі. Публікації під час тесту вимкнені. Окремо записати `elapsed_ms` від початку передачі до готового результату, час модельних етапів, фактичні токени та вебвиклики LOTNEXO і ручні дії. Для ChatGPT записати діючу підписку або план, режим і час, залишити `cost_usd` невідомим, якщо немає ціни окремої відповіді.

## Звірка результатів

Незалежний оцінювач фіксує еталонний JSON і допустимі формулювання до відкриття відповідей. Він звіряє номери фото, джерела та статус кожного факту. Назву загального типу й точну модель оцінює окремо. Імовірні характеристики й непідтверджені посилання залишає видимими в діагностиці. Характеристику без достатнього доказу зараховує як невизначену або помилкову згідно з протоколом. Точну ідентифікацію вважає підтвердженою за правильним предметом і варіантом, якщо його встановлено в еталоні. Для еталонного критичного рішення eBay потрібна звірена листова категорія.

```sh
python recognition_benchmark.py reference.json lotnexo.json \
  --chatgpt-predictions chatgpt.json --min-admission-rate "$admission_rate"
```

На трьох лотах перевірити проходження фото, цитат і невідомих до картки. На десяти вибрати модель та правила маршрутизації. Після цього зафіксувати конфігурацію й оцінити окремі 50 лотів, виключивши налаштувальні лоти та дублікати предметів. Зафіксувати точність і покриття окремо за кожним полем, P50/P95 часу, витрати за фактичними лічильниками і кількість невизначених. Порогове приймання охоплює рівень ChatGPT, ≥90% ідентифікацій та нуль критичних категорій серед допущених. [Критерії та бюджет](../../MASTER_PLAN.md)
